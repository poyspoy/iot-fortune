# Existing Baseline Defects (มีอยู่แล้วใน `7555525` — ไม่ได้เกิดจากงานรอบนี้)

## BD-001 การจับคู่ Telemetry ด้วย sourceKey ไม่บังคับความเป็นเอกลักษณ์ครบทุกระดับ

| | |
|---|---|
| สถานะ | **Existing Baseline Defect** — บันทึก 19 ต.ค. 2569 · แก้ใน Data Layer (Commit 2) |
| ที่อยู่ | `src/domain/config.js` (`indexConfig`, `validateConfig`) · `src/domain/normalize.js` |
| ผลต่อ Fortune ปัจจุบัน | **ไม่มี** — ตรวจข้อมูล Fortune แล้วไม่มี `(projectId, sourceKey, metricSourceKey)` ซ้ำ (ด้านล่าง) |

**รายละเอียด (ตรวจโค้ดจริงแล้ว — ละเอียดกว่าที่รายงานไว้ก่อนหน้า)**

1. ระดับจุด: `validateConfig` **ตรวจ sourceKey ของจุดซ้ำอยู่แล้ว** และทุกทางที่รับการตั้งค่า (เริ่มแอป, บันทึกจากหน้า "ตั้งค่า", นำเข้าไฟล์สำรอง) เรียก `validateConfig` ก่อนใช้ — ดังนั้นกรณี "จุดหลังทับจุดแรก" จะเกิดได้เฉพาะเมื่อมีโค้ดส่งการตั้งค่าที่ยังไม่ผ่านการตรวจเข้า `indexConfig` โดยตรง (`indexConfig` ใช้ `Map.set` ทับเงียบ ๆ ไม่ป้องกันตัวเอง) — เป็นช่องโหว่เชิงป้องกัน ไม่ใช่สิ่งที่เกิดในการใช้งานปัจจุบัน
2. ระดับค่าวัด: **`validateConfig` ไม่ตรวจ `metric.sourceKey` ซ้ำภายในจุดเดียวกัน** (ตรวจเฉพาะ `metric.id` ซ้ำ) — ถ้าค่าวัดสองค่าในจุดเดียวมี sourceKey เดียวกัน การตั้งค่าผ่านการตรวจ แต่ข้อมูลทั้งหมดเข้าค่าวัดแรก ค่าวัดที่สองไม่ได้รับข้อมูลเลยโดยไม่มีข้อความเตือน (ทดลองแล้ว: P-005 ตั้ง `rh.sourceKey = 'temp'` → `valid = true`, ข้อมูล `temp` เข้า `temp` เท่านั้น)
3. ไม่มีแนวคิด projectId ในการจับคู่ (ระบบมีโครงการเดียว)

**แนวทางแก้ (ตาม DATA-LAYER-PLAN ข้อ 2.3)**: ดัชนี `(projectId, sourceKey, metricSourceKey) → (pointId, metricId)` ที่ตรวจซ้ำก่อนสร้าง · ซ้ำ = การตั้งค่าไม่ผ่าน (ไม่เลือกให้เอง) · Unit Test ครอบคลุมทั้ง 3 ข้อ

**ผลตรวจข้อมูล Fortune ปัจจุบัน (`createDefaultConfig()` ของ `7555525`)**

- 8 จุด · 12 ค่าวัด · 12 คู่ `(sourceKey, metricSourceKey)` **ไม่ซ้ำ** · ไม่มีจุดใดใช้ sourceKey ร่วมกัน · projectId เดียว
- `WL-001|level` · `WL-002|level` · `P-003|run` · `P-003|current` · `P-004|chws` · `P-004|chwr` · `P-005|temp` · `P-005|rh` · `P-006|power` · `P-006|energy` · `P-007|temp` · `P-008|leak`
- หมายเหตุ: การตั้งค่าที่ผู้ใช้แก้เองในเบราว์เซอร์แต่ละเครื่อง (IndexedDB) ตรวจจากที่นี่ไม่ได้ → Migration v6 ต้องตรวจคู่ซ้ำก่อนอัปเกรด ถ้าพบ **หยุดการอัปเกรด แสดงรายการจุด/ค่าวัดที่ชนกัน และคงฐานข้อมูลเดิมไว้** (ไม่เลือก ไม่เขียนทับ)

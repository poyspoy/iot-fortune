## ขอบเขตโมดูล 0

1. **ID ภายในเป็น UUID**: Engine, ค่าวัด, เหตุการณ์, การรับทราบ, สถานะหน้าจอ อ้างจุดด้วย UUID · รหัส (P-003) ใช้แสดงผลเท่านั้น · aria/ข้อความบนหน้าจอยังแสดงรหัสเดิม (e2e เดิมผ่านโดยไม่แก้)
2. **ฐานข้อมูล `<เดิม>@v6`** (ฟังก์ชันจาก Commit 3 `migrateDb.js`): คัดลอก + แปลง ไม่แก้ฐานเดิม
3. **Overlay → ข้อมูลจริงใน v6**: สถานะติดตั้ง / ตำแหน่ง / `resolvedAgainst` เก็บในเอกสาร v6 (เลิก overlay)
4. **Audit การปฏิเสธข้อมูลบันทึกถาวร** ในสโตร์ `rejected_ingestion` (จำกัดจำนวน/อายุ)
5. Device แยกจาก Monitoring Point ในเอกสาร v6 (ตามคำตัดสินข้อ 2) — Fortune ยังไม่มี Device จริง → สร้าง Device สาธิต 1 ตัวต่อจุด (`isDemo`) เพื่อให้กติกา "ติดตั้งแล้วต้องมี Device" สอดคล้อง

## ขั้นตอนย้ายข้อมูล (ทำงานในเบราว์เซอร์ของผู้ใช้แต่ละเครื่อง)

| ขั้น | ทำอะไร | ล้มเหลวแล้วเป็นอย่างไร |
|---|---|---|
| 1 Backup | ก่อนแตะอะไร: ส่งออกฐานเดิมทั้งก้อน (config, settings, ค่าวัด, เหตุการณ์, การรับทราบ, ui, overlay) เป็น JSON + SHA-256 เก็บใน `@v6` kv `migration.backup.v5` **และ** ให้ดาวน์โหลดไฟล์สำรองได้จากหน้า "ตั้งค่า" | ยังไม่สร้าง `@v6` · ใช้ฐานเดิมต่อ |
| 2 Pre-check | ตรวจคีย์ข้อมูลเข้าชนกัน (BD-001), การอ้างอิงที่หาไม่พบ, จำนวนข้อมูล | พบปัญหา = หยุด แสดงรายการ ไม่เลือกแทนผู้ใช้ |
| 3 Dry Run | แปลงทั้งหมดในหน่วยความจำ (ไม่เขียน) แล้วตรวจย้อนกลับ: แปลง v6 → มุมมอง v5 ต้องเท่าข้อมูลเดิมทุกค่า | ไม่ตรง = หยุด แสดงจุดที่ต่าง |
| 4 Migration Report | ก่อนกดยืนยัน: จำนวนจุด/ค่าวัด/เหตุการณ์/การรับทราบ ก่อน–หลัง, ตาราง รหัส → UUID, รายการที่ผู้ใช้แก้เอง (ชื่อ ตำแหน่ง เกณฑ์ จุดที่เพิ่มเอง) ที่จะถูกคงไว้, คำเตือน | ผู้ใช้ไม่ยืนยัน = ไม่ย้าย |
| 5 Migrate | เขียน `@v6` ในธุรกรรมเดียว (ผิดพลาด = ลบ `@v6` ที่เขียนไม่ครบ) | ฐานเดิมไม่ถูกแตะ |
| 6 Verify | เปิดแอปบน `@v6` แล้วเทียบ: KPI, สถานะหมุด, กราฟ (จำนวนจุด/ค่าแรก/ค่าสุดท้ายต่อค่าวัด), รายการแจ้งเตือน + การรับทราบ เท่ากับก่อนย้าย | ไม่เท่า = Rollback อัตโนมัติ + รายงาน |
| 7 Rollback | ปุ่ม "ย้อนกลับไปข้อมูลเดิม" (ลบ `@v6`) ใช้ได้ตลอดช่วงทดลอง · build เดิม (`7555525`/Demo) อ่านฐานเดิมได้ทันทีเพราะไม่เคยถูกแก้ | — |
